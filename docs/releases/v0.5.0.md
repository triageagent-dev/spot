Durable engine on Temporal, a timeline of each wake, and payloads that never leave the pod.

**Temporal engine** (`--engine=temporal`, off by default)
- The schedule and every turn run as a Temporal workflow, so a restart resumes where the spot was. Model and tool calls are activities.
- Two lanes: a person's message runs on a short lane while a long turn works. Continue-as-new keeps the history bounded.
- Works with Temporal Cloud (API key from a file) or a self-hosted server.

**Payloads stay in the pod** (`--temporal-local-payloads`, chart `engine.temporal.localPayloads`)
- The history holds only a reference to each payload; the content is a file in the spot's state directory and never reaches the Temporal service. Unread payloads are removed after 21 days.
- The alternative is the existing AES-GCM codec (`--temporal-payload-key-file`). Switching modes needs a fresh workflow: history written with the other codec cannot be replayed.

**Wake timeline**
- Each wake sends the core one line: reason, lane, outcome, duration, steps, tool calls, tokens, and the next wake. A client can draw what the spot did and when.

**Cost**
- A quiet wake (nothing new) makes no model call.
- Tool results are capped at 12 KB, and `--hourly-token-ceiling` stops a runaway hour.

**Fixes**
- A bare tool name the instruction uses resolves to the one server that offers it.
- Temporal workflow and run ids appear on the root span of a turn.
