Tasks: the agent can start work that runs beside its turn, and an operator can control it.

**Tasks** (temporal engine, `--max-tasks`, chart `engine.temporal.maxTasks`, default 3, 0 turns them off)
- A new built-in tool, `start_task` (title, goal), lets the agent hand a long job to a turn of its own. The task runs as its own workflow beside the wake that asked for it, so a person's message is never stuck behind a long check.
- A task starts with only its goal, the standing notes and the digest, uses the same tools and caps as any turn, and cannot schedule wakes or start tasks. Up to 3 are requested per turn, up to 10 wait in the queue.
- A task ends with one `finish` line. It goes into the digest and the core gets a wake line with lane `task`.
- A spot under a hold rule runs no tasks.

**Control from the core**
- The core can list, stop, kill, restart and drop the tasks of a spot (new `control` and `controlResult` frames on the stream). Stop ends a task at the next step, kill terminates its workflow, restart runs it again from its goal, drop removes a queued one. Every request gets one answer within 8 seconds, refusals included.
- A stopped task is reported as stopped, not as a failure.

**Release**
- A release now publishes its notes from `docs/releases/<tag>.md` and fails without that file.
