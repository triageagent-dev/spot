Fixes for a spot on Agent Substrate that did not answer, and for a message meant for another spot.

**A spot on Agent Substrate**
- The room cursors are saved when the actor starts. An actor is a new process on every wake and does not poll while the core's stream is up, so a room was first read by the wake after the one that should have answered, and that read dropped the message as history. An empty room gets a cursor too, and the message that wakes a process with no cursor is news, not history.
- A core that cannot be reached is no longer taken for a core without the room tool, which disabled the room for ten minutes.
- A wake the core orders reads the rooms. A frame the actor takes for a poke (no usable token) became a plain tick that read nothing of it; what is waiting in the rooms is now a fact of that wake, and a person's message runs it as a human wake.

**A message for another spot**
- With `forYou` and `mentions` on a room message (core 3.5.281 and later) the spot answers only a message the core says is for it, and the wake prompt says a message that names another spot is not for this one.

**Docs**
- `docs/spec.md` describes the enrolment of a substrate spot: the one-time key, its Secret, the join, the re-key and the name.
