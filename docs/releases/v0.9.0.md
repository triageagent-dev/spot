Tria fronts the workspace: the spot speaks to Tria in its own bus room, and long work runs in task actors (the core's ADR-109).

**Needs a core that serves the bus (ADR-109 phase 1) and the new system prompt.** The spot reads and speaks in one room, `bus`, and no other. On a core without it the spot hears nothing. Render the prompt with `make prompt-cell` and apply the cell before the spots move to this image.

- **One room.** The team and agents rooms are gone from the supervisor. Every message in the bus is Tria's request, made for a person or for the workspace, and wakes the spot at once as someone asking. The wake names the request id, the person it is made for and the issue; the model answers with `say_in_workspace` (`room: "bus"`, `reply_to` the request id, `memory` the id of a note when the answer rests on one). The tools take `bus` and no other room, and no spot name.
- **Requests for later.** A request that names a later time (`due`) is not a wake: it becomes a promise whose entry names the request, and the core starts the piece then. One that is too far out or past the 20 is read at once and the model is told so.
- **Promises are a list.** Up to 20, each at most seven days out, sorted by time; the earliest is the next wake, a fired one is removed, and no request moves another. They are reported as `promises` in the schedule and in every wake report, and kept in `promises.json` (an earlier `promise.json` is read as a list of one). An earlier wake the agent asked for on its own is still not pushed back by an edge wake, but it is no promise.
- **Task actors.** `--task-verifier-file` makes a process an actor the core made for one task. It never joins. It takes the first request whose bearer hashes to the SHA-256 in that file, runs the goal in one turn, writes the result as one memory item (kind `note`, the task key as its subject), answers the request in the bus with the item's id, and sends one wake report that carries the key. The token is for this task and this workspace only: the spot's calls to the core always go with its own workspace, and a call to another room is refused.
- **`start_task` on a substrate spot** asks the core to make that actor (`POST /v2/messenger/spot/link/tasks`). The result goes to Tria, not to the spot's digest. On a deployment it is unchanged.
- A cold actor that reports a promise without having run a wake says its last plan back, from its window, so the report does not replace the core's plan with nothing.

Not in this release: the name of the setting through which the core hands the task verifier to an actor is the core's phase 3; the flag takes a file path until then.
