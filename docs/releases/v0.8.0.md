The spot can run as an actor of Agent Substrate (the core's ADR-107), beside the Deployment runtime, which is unchanged.

**A spot on Agent Substrate**
- `--runtime substrate` serves HTTP on `--listen` (`GET /readyz`, `POST /frame`) and talks to the core in requests instead of a websocket: `POST /v2/messenger/spot/link` (challenge, join, renew, hello) and `POST /v2/messenger/spot/link/report`. The platform suspends an idle actor and resumes it on the core's next request.
- There is no startup wake and no timer of its own: the core's schedule (ADR-106) is the only clock. Reports (turns, stats, wake reports last) are sent when the supervisor is idle. `/state/supervisor/window.json` keeps the hourly token samples, the early wakes and the issue baseline across suspensions.
- The actor holds no credential. `--llm-auth injected` sends a placeholder `x-api-key` to api.anthropic.com, `--enroll-key-injected` puts a placeholder `X-Triage-Enroll-Key` on the first join, `--otel-token-injected` a placeholder bearer on OTLP and the ego MCP; the egress policy replaces each from a Secret.
- `--connectors-json` gives the connectors inline for a runtime with no file to read.
- Install: the two manifests in `deploy/substrate/` (an ActorTemplate and an EgressPolicy, with placeholders), applied with `kubectl ate`. The Helm chart installs the Deployment runtime only and is unchanged.

Upgrade: image `ghcr.io/triageagent-dev/spot:0.8.0`, chart `oci://ghcr.io/triageagent-dev/charts/tria-spot` 0.8.0. A Deployment spot needs nothing new. A spot on substrate needs a core that has the spot link (ADR-107) and one-time key per spot.
