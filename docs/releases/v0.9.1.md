Every listener of the spot is plain TCP.

- **No Multipath TCP.** Go 1.24 and later ask the Linux kernel for a Multipath TCP socket on every listener. The kernel bug CVE-2026-98432 (a use-after-free in IPv4 TCP connection setup, CVSS 9.8, fixed in kernels 5.10.272, 5.15.223, 6.1.190, 6.6.159, 6.12.113 and 6.18.56) is reached, as far as the published exploit goes, through such a listener. The spot now sets `godebug multipathtcp=0` in its module, so no binary built from it opens one. Nothing changes on the wire for a client; a patched kernel stays the fix.

Nothing else changed since v0.9.0.
